# あゆみ「段階ごとの覚えた語」を語彙力の目安にする — 設計案（2026-11-08・ホーム・あゆみ部門・実装はオーナー判断後）

オーナーの言葉（受付経由 2026-11-08）: 「単語リストに追加されていなくて学習をしていないが、知っていると推測される単語もたくさんあると思う。それらを自動で判定して A2 や A1 など空白になってしまう部分を補完して、この機能を自分の語彙力を測る目安にしたい」。

## 0. 結論（先に）

- **推奨は (c)。ただし土台は (b) 短い語彙チェック（任意・1〜2分）で、(a) 既存データは補正と「チェックを省ける根拠」にとどめる。**
  理由: 今あるデータは「知っている」側の証拠がほとんど無い。A1/A2 が空白になる原因そのもの（帯フィルタで下の段階の語を出さない＝採点もスキップも起きない）なので、(a) だけでは自己申告（TOEIC の設定）を塗り直すだけになる。
- **推定は「語数」ではなく「段階ごとの知っている割合の帯」として持ち、画面では3段階の印で出す**（◎ ほぼ知っている／○ 半分くらい／（印なし）まだ測っていない）。語数にすると表の語数を分母に出すことになり、分母を見せない方針（10/8・11/05）と合わない。
- **「学習して覚えた」と「知っていると推定」は別物として分ける**: 覚えた＝今の金色の棒と数字のまま。推定＝棒の右端の印＋別の凡例「知っていると推定（語彙チェックから）」。推定に数字は付けない。
- 既存の円・EXP・草・SRS・cl_stats_daily には一切混ぜない（新しいキー1つ）。
- 11月末に予定している「いまの目安」（firstQuality×頻度でスコア帯）は、この語彙チェックの結果を土台にすると一本化できる（別々に2つの目安を出さない）。

## 1. 推定の方法と得失

### (a) 今あるデータから推す

| データ | 何が分かるか | 弱点 |
|---|---|---|
| 「知ってる」で飛ばした語（cl_srs skipped）| 明示的な既知。語の段階（levelShown / AI level）も履歴にある | 件数が少ない。帯フィルタで下の段階の語はそもそも画面に出ないので、A1/A2 の記録はほぼ無い |
| 予習で基礎語として自動除外された語（lib/wordlist.js NGSL tier・TOEIC 設定から）| — | 利用者の自己申告（TOEIC）の写し＝循環。同じ設定なら全員同じで、本人の語彙の証拠にならない |
| 帯フィルタで隠した語（下の段階の語）| 「知っているはず」として隠した語そのもの | 履歴には表示した語（selected）しか保存していない（VocabScreen saveHistoryEntry）＝今は使えない。生成時に段階別の件数だけ記録する手はあるが、これも設定由来で循環 |
| 初回体験・アンケートのレベル選び（settings.toeicScore / userLevel）| 本人の自己申告 | 先験値としてなら使える（「A2 以下はほぼ知っているだろう」の初期値）。証拠ではない |
| 復習の成績（firstQuality × 段階＝lib/levelEstimate.js 実装済み・未接続）| 段階ごとの「初見で知ってた率」。上の段階の率が高ければ下も知っているとみなせる（CEFR-J の段階設計上おおむね単調） | 段階あたり 10 語以上の firstQuality が要る。B1 以上は溜まるが A1/A2 は帯で出ないので溜まらない＝埋めたい所ほどデータが無い |

- 得失: 手間 小（0.5〜1日）・利用者の負担 ゼロ・精度 低（A1/A2 は自己申告に近い）。
- 使いどころ: (b) の結果の**補正**（例: B1 の firstQuality 既知率が 80% 以上なら A1/A2 のチェックを省いて「ほぼ知っている」としてよい）と、**整合の確認**（チェックの結果と復習の成績が大きく食い違えば測り直しを勧める）。

### (b) 短い語彙チェック（Yes/No 形式・擬似語で当て推量を補正）

- 形: 画面に語を1つずつ出し「知っている／知らない」を押す。各段階 8 語 × 6 段階 ＝ 48 語 ＋ 擬似語（実在しない英語らしい綴り）8〜12 語。1〜2 分。途中でやめられる（やめた分は「まだ」）。
- 補正: 擬似語に「知っている」と答えた割合で各段階の既知率を割り引く（語彙サイズテストの一般的な方法）。擬似語の既知率が高すぎる（例 40% 超）回は結果を採用せず「もう一度いつでも」とだけ出す。
- 出題語の出どころ（候補。どれを使えるかは法務確認中＝論点はリポジトリ外で管理）:
  - b1: CEFR-J / Octanove の表から各段階ランダム抽出。
  - b2: 共有キャッシュ（vocab_cache）の語に表の段階を付けてサーバが抽出。A1 の基礎語は生成時に除外されがちで出題数が足りない可能性＝実測が要る。
  - b3: A1〜B1 は同梱済みの NGSL の tier0/400/600 から、B2〜C2 は本人の履歴にある語（levelShown つき）から。新しい出典が増えない。**第1版はこれを推奨**。
  - 擬似語は自作（例: plandle / crimbet のような非語）。外部の疑似語リストは使わない。
- 精度: 段階あたり 8 語では既知率の誤差が大きい（90% 幅で ±30pt 程度）。だから出すのは3段階の印まで。語数や % は出さない。
- 得失: 手間 中（2〜3日）・負担 1〜2分（任意）・精度 中（3段階の印なら足りる）。

### (c) 組み合わせ・測り直し

- 語彙チェックを土台にし、(a) の firstQuality で補正。測り直しは本人が押す「もう一度チェック」だけ（30日に1回まで）。自動で促さない・期限を出さない。
- 「学習して覚えた」は別に積み続ける（今の棒）。チェックの結果は上書きしない。
- 得失: 手間 3〜3.5日・精度は (b) と同じ。推奨。

## 2. 表示の分け方（案）

- 今の横棒（覚えた＝金・うちマスター＝濃金・数字は覚えた数）は**そのまま**。棒の長さの定義（最多の段階を 1 とした相対値）も変えない。
- 各段階の右端に推定の印を1つ: ◎「ほぼ知っている」／○「半分くらい」／印なし「まだ測っていない」。色は金系の薄い色で、覚えたの金と区別できる形（印であって棒ではない）。
- 凡例に1行追加: 「◎○＝知っていると推定（語彙チェック○月○日）」。推定に語数・% は付けない。
- 注記: CefrNote（CEFR-J・Octanove・出典）はそのまま。その外の1行「目安の付かない語（句動詞など）は含みません」もそのまま。チェック未実施の人には印も凡例も出さず、カードの下に小さく「語彙チェック（1〜2分）で、学習していない段階の目安も出せます」のボタンだけ。
- やらない表示: 「あなたは B1」「A1 はほぼ完了」「残り ○語」「表の語数に対する %」。
- モック: 実装判断が出たら reports/ に作る（今回は文で）。

## 3. 罪悪感を与えない

- チェックは任意・途中でやめられる・結果は「まだ」ではなく「これから出会う段階」と言う。低い結果でも色を変えない。
- 測り直しは本人から。前回より下がっても前回の印を赤くしない（新しい結果に置き換えるだけ・履歴を見せない）。
- 人と比べる表示・ランキング・平均は出さない。

## 4. 既存の仕組みとの分離

- 新キー `cl_level_estimate`: `{ at, version, byLevel: { A1: { asked, known }, … }, pseudo: { asked, known }, source: 'test' }`。端末＋user_state で同期（at が新しい方・lib/stateMergeRules.js に1関数）。ログアウトで消す対象（lib/deviceAccount.js LEARNING_KEY_RE）に足す。
- チェックで出した語は SRS・履歴・単語帳・EXP・cl_stats_daily・cl_exp_ledger に**書かない**。円の「出会った」にも入れない（出会った＝作品で出会った語）。
- firstQuality は読むだけ（補正用）。
- 計測: `journey_level_check_done`（完了）・`journey_level_check_skip`（途中でやめた）の固定名2つ。段階や結果の値は名前にも値にも入れない。
