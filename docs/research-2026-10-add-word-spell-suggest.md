# 「単語を追加」の綴りミス候補 — 設計と実測（2026-10-30・作品・予習部門）

依頼: 受付経由のオーナー要望（2026-10-30）。単語リストの「単語を追加」で入力した語が字幕に見つからない時、その話の字幕の語から綴りの近い候補を例文つきで出し、「この語ですか？」と確認できるようにする。
**状態: 設計と試作（実測スクリプト・モック）まで。コード変更なし・本番未反映。** 法務の回答（2026-10-30・受付経由・backlog に記録）は「vocab_cache は OK／raw キャッシュは条件付き OK」。下の設計と数字は、その条件に合わせたもの。

## 0. 結論

- **案A（リストの語だけ・法務 OK）**: 画面の中で、この話の単語リストの語との近さを見る。リストにある語の綴りミスは **96%** を拾える。ただし、足したい語（リストに無い語）の綴りミスは **0%**。足したい語は、そもそもリストに無い語だから。工数は 0.75日。
- **案B（案A＋その話の字幕の語・法務の条件付き OK）**: リストに無い語の綴りミスでも、1か所のミスなら **上位3件に 97%**、2か所なら **76%** が入る。例文を付ける「最も近い1候補」が正しい語なのは **96%**。工数は 案A込みで 約2.5日。
- オーナーの「綴りミスで追加できない、を無くしたい」に応えられるのは **案B**（推奨）。案A は単独では、ほぼ効かない。

## 1. 今の流れ（2026-10-30 時点のコード）

- 画面 `components/VocabScreen.js` `handleAddWord` → `POST /api/example`（`mode:'manual'`）。
- サーバ `app/api/example/route.js`:
  - 層1: vocab_cache の字幕語（drama）と語形込みで一致すれば、その例文。
  - 層2: ログイン必須。`manualWordProblem`（3字未満・複数語・頻出語は不可）を通った語だけ、raw キャッシュ（無ければ取り直し枠の範囲で1回取得）から**完全一致（活用形込み）の1文**を返す。上限は `EXAMPLE_MANUAL_LIMITS`（1人×1話 20/日・1話全体 60/日・1分 10）。
- 見つからなければ `no_match` になり、**入力どおりの綴りで例文なしのまま保存**される。
- 画面の「すでにこの話のリストにあります」は完全一致しか見ていない。

## 2. 実測（本番データを読み取りのみ・作業用フォルダで）

- 対象: raw キャッシュがある6本。Suits S1E6、Friends S1E1（リスト無し）、Breaking Bad S1E1、プラダを着た悪魔、Loki S1E1、ファルコン＆ウィンター・ソルジャー S1E1。
- 「足したい語」は、字幕にあってリストに無い語。4字以上で、頻出語・固有名詞（8割以上が大文字始まり）は除く。1話あたり 125〜365語で、そこから1話40語まで無作為に選んだ。
- 綴りミスは6種類を機械的に作った: 1字抜け／重ね字の過不足／隣の字の入れ替え／母音の取り違え／キーボードの隣のキー／音の綴り違い（ph→f・-tion→-sion・-ence↔-ance・ie↔ei など）。ミスの結果がたまたま字幕にある別の語になった場合は除外した。
- 判定は法務の条件どおりにした: 入力4字以上・編集距離は 5字以下=1／6字以上=2・頻出語と3字以下を除く・候補最大3。
- スクリプト: `reports/add-word-spell-mock/measure/measure_legal.mjs`（git 管理外）。

| 綴りミスの対象 | 候補の取り元 | 1か所ミス：最も近い1候補が正解 | 1か所ミス：上位3件に正解 | 2か所ミス：上位3件に正解 |
|---|---|---|---|---|
| リストに無い語（足したい語・211語） | リストの語だけ（案A） | 0% | 0% | 0% |
| リストに無い語（足したい語・211語） | ＋その話の字幕の語（案B） | 96% | 97% | 76% |
| リストにある語（172語） | リストの語だけ（案A） | — | 96% | — |

- 種類別（案B・1か所ミス・上位3件）: 1字抜け 83%、ほかの5種類は 100%。1字抜けの取りこぼしは、4字の語から1字抜けて3字になり、入力4字以上の条件で候補を出さない分。
- 2か所ミスで外れるのは主に短い語（`clnb`→climb、`wekc`→wreck など）。距離の条件の外なので追わない。
- 例: suspiciun→suspicion・suspicious／handkuffs→handcuffs／gntlemen→gentlemen／reileved→relieved／tradrr→trader・trades・grader。
- **正しく綴った実在の語で、その話に無いもの**を入れた場合も、11%で候補が出る（平均 1.3語。例: soap→soup）。「どれでもない」で抜けられる。これが、字幕の語を探り出すのに使える入口の大きさでもある（§5）。
- 参考（法務の条件より広い判定）: 10字以上の語に距離3まで許し、音の綴り違いを距離1とみなすと、1か所ミスは 100%、2か所ミスは 81% になる。差が小さいので、法務の条件のままで十分。
- 限界: ミスは機械的に作ったもので、実際の利用者のログではない。affect/effect のような「別の実在語との取り違え」は、入力した語が字幕にあればそのまま当たるので、この機能の対象外。

## 3. 出し方（モック: `reports/add-word-spell-mock/スマホ-候補シート（モック）.jpg`）

1. **案A（画面の中だけ）**: 追加ボタンを押したら、まずこの話のリストの語との近さを見る。近い語があれば「リストにある jeopardy ですか？」と出し、その語の行へ飛ぶ（追加はしない）。サーバには聞かない。
2. **案B**: リストに近い語が無ければ、今までどおり `/api/example` に1回聞く。層1・層2の完全一致（活用形込み）が無い時だけ、同じ要求の中でサーバが字幕の語から候補を作る。**要求を1回増やさない。**
   - 応答: `{ found:false, reason:'no_match', suggestions:[{ word, sentence?, tsSec?, tsLabel? }] }`。候補は最大3語。**例文と時刻は最も近い1候補だけ**（法務の条件）。`trimExampleToSentence`（200字）を通す。
   - 画面: 入力欄の下にシートを出す。「『suspiciun』はこの話の字幕に見つかりませんでした。この語ですか？」
     - 1番目の候補: 語・📍時刻・例文（語を強調）・出典（📺 作品 SxE（字幕：OpenSubtitles）＝48条）・「この語で追加」。
     - 2・3番目の候補: 語と「この語で追加」だけ。選ぶと、その語で今までどおり手動追加の照合をする（完全一致の1文が付く・上限も今までどおり数える）。
     - 最後に「どれでもない（入力のまま例文なしで追加）」。
   - 選んだら、今の「追加直後のカード（意味・例文・発音）」へそのまま進む。選ばなかった候補の文は保存しない（法務の条件）。
3. 候補が0件なら、今までと同じ（例文なしで追加し、理由を一言添える）。

## 4. 近さの判定（工数つき）

| 項目 | 中身 | 工数 |
|---|---|---|
| 編集距離 | OSA（隣の字の入れ替えを1と数える）。許す距離は 5字以下=1・6字以上=2。入力4字未満は候補を出さない（法務の条件） | 0.3日 |
| 語形変化 | 同じ語の活用形（suspicion/suspicions など）は `wordStems` で1つにまとめる。表示するのは字幕に実際に出た形。「原形を入れたが字幕は -ing 形」は今の一致処理（活用形込み）で既に当たるので、綴りミスの扱いは要らない | 0.2日 |
| 大文字小文字・記号 | 入力も字幕も小文字にそろえ、アポストロフィを統一。固有名詞（8割以上が大文字始まり）・頻出語（`COMMON_WORDS`）・3字以下は候補にしない | 0.1日 |
| 並べ順 | 距離 → 先頭の字が同じ（綴りミスで頭文字が変わることは少ない）→ その話での出現回数 | 含む |
| テスト | 実データの綴りミス表（上の6本）で回帰テスト | 0.3日 |
| サーバへの組み込み（案B） | `no_match` の分岐に候補作りを足す・見せた文の数で上限を数える | 0.5日 |
| 画面 | 候補シート（案B）0.75日・リスト内の綴りチェック（案A）0.25日 | 1日 |

- 案A だけなら 約0.75日（画面の中の判定 0.3日 ＋ リスト内チェックの画面 0.25日 ＋ テスト 0.2日）。
- 案B（案A込み）は 約2.5日。
- 計算は1話の字幕（30〜150KB・異なる語 150〜450）に対して数ミリ秒。Claude や外部 API の費用は増えない。字幕の取り直し枠（DL 枠）も増やさない（法務の条件）。

## 5. 字幕を探り出す使われ方への対策（法務の条件に沿って）

- **見せた文の数で数える**: 候補につけて返した例文（最大1文）を、今の手動追加の上限（1人×1話 20/日・1話全体 60/日）の1つに数える。1日に引き出せる文の総数は今と同じ。
- **入力に近い語しか返さない**: 距離の条件の外の語は返さない。任意の語を入れて字幕の語の一覧を引き出すことはできない（正しく綴った実在の語で候補が出るのは 11%・平均 1.3語）。
- **条件は今の層2と同じ**: ログイン必須・頻出語や3字以下は不可。入力は4字以上。
- **返すのは語と1文だけ**: 前後の文や、全出現の時刻の並びは返さない。時刻も最も近い1候補の1つだけ。
- 候補は保存も共有キャッシュへの書き込みもしない。ログには件数だけを残す（語や本文は残さない）。
- 層1（vocab_cache）を先に見る（法務の条件）＝今の順番のまま。

## 6. オーナーに決めてほしいこと

1. **案B（推奨）**: 案A＋字幕の語から候補。リストに無い語の綴りミスも 97% 拾える。約2.5日。
2. 案A だけ: リストにある語の綴りミスだけ拾う。約0.75日。足したい語の綴りミスは拾えない。
