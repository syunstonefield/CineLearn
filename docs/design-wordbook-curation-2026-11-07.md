# マイ単語帳を「自分で選んだ語とセリフの場所」にする設計案（2026-11-07・③単語帳部門）

法務の回答（2026-11-07）を反映済み：セリフだけの棚は作らず「語に付いた例文に♡」の形にする（3 節）。

オーナーの見立て（受付経由）：「拡張から保存した単語が全部自動で反映されるので開く意味がない。特に覚えたい単語やお気に入りのセリフを保存できれば開く意味ができる」。
方向＝単語帳を「保存したもの全部の置き場」から「自分で選んだ、特に覚えたい語・お気に入りのセリフの場所」へ。実装はオーナー判断後。

## 0. 現状の構造（コードで確認・2026-11-07）
- `my_words.in_wordbook`（既定 true）＝単語帳に出すか。★（単語リストの `starWord`/`unstarWord`・2026-09-22）がこの旗を立てる／倒す。拡張の保存は列を送らない→DB 既定の true で自動的に単語帳へ。
- 旗を見るのは **単語帳の画面（getWordbookWords）・下タブの件数（getActiveWordCount）・単語リストの★表示（VocabScreen）** の3か所だけ。
- 復習（ReviewHub・今日の復習）・あゆみの円（collectRingWords）・リユニオン・書き出し（export）は **getActiveWords＝旗に関係なく保存語ぜんぶ**を使う。→ 旗を倒しても語は消えず、復習・円の「出会った」・SRS は変わらない。
- 拡張 background.js:67 は「他作品で出会った語」の印のために `my_words?in_wordbook=is.true` を引く（クラウドの★だけ）。同じ端末で保存した語は拡張のローカルにもあるので印は残る。別端末で拡張保存→未★の語だけ、他作品での再会の印から落ちる（下の 5 で扱う）。

## 1. 拡張で保存した語を単語帳に自動で入れない形
**案 A（推奨）: DB の既定を変える＝`ALTER TABLE my_words ALTER COLUMN in_wordbook SET DEFAULT false`。**
- 拡張は列を送らない→新しい保存語は false（単語帳に出ない）。拡張の変更は不要。
- アプリの★（starWord）は true を明示して送る（今もそう）。アプリの手動追加（addManualWord・スマホから単語を追加）は本人の意思なので `inWordbook: true` を明示して送る（1行足す）。
- pull 側は「列が boolean ならその値」なので変更なし。列が無い旧DBでの既定 `?? true` もそのまま。
- **語の行き先**: 作品の単語リスト（✏️追加 チップ付き・今と同じ）・復習・円・リユニオン・CSV に残る。消えるものは無い。
- **既存の語（今 true の大量の語）**: ALTER の既定変更は既存行に触らないので **そのまま残る**（勝手に消さない）。整理は任意で1回だけ：単語帳を最初に開いた時に「単語帳を『特に覚えたい語』の場所にしました。今入っている N 語は [このまま残す] [★の語だけにする]」の2択（★の語だけ＝source が 'star' 以外（ext/manual）の旗を倒す。語は作品のリストと復習に残る、と一行で明記）。赤バッジ・「たまっています」等の表現は使わない。選ばなければ何もしない。
- 一括で旗を倒す処理は N 行の upsert になるので、pushMyWord の1行ずつではなく配列で1回の POST にする小さな関数を足す（merge-duplicates で in_wordbook だけ送る）。
- 代替案 B（アプリ側で「source==='ext' かつ本人が★していない語は出さない」）は、DB の既定 true と本人の★ true を区別できないので不可。区別するには列（starred_at 等）が要り、A より重い。

## 2. 「特に覚えたい」の付け方＝★に一本化
- ★＝「単語帳に入れる」の意味を「特に覚えたい」と同じにする（今の★をそのまま使う。新しい印は作らない）。文言は「★ 単語帳に入れる」→「★ 特に覚えたい」に寄せる（VocabItem のトグル）。
- 付けられる場所（アプリ・拡張の変更なし）：①単語リストのカード（済）②単語帳のカード（済）③ホームの今日の語（TodayPanel・済）④**復習カード（ReviewModal）に★を追加**＝「思い出せなかった→特に覚えたい」が一番自然な瞬間 ⑤**予習カード（PrepWalkthrough）に★を追加**。
- 拡張のポップアップ（単語クリック時）に「★ 特に覚えたい」を足すのは拡張の変更（v1.2.12 以降）。それまでは「保存」＝リストと復習に入る、★はアプリで、という分担。

## 3. 「♡を付けた語（例文つき）」＝お気に入りの例文の印（法務 条件付きOK・2026-11-07）
- セリフだけを集める棚・カードは作らない。♡は**例文のある語に付ける印**（語が必須）。見せる時は語が見出し、例文は “ ” と 📺作品 SxE（字幕：OpenSubtitles）付きの従（今の VocabItem の形のまま）。
- 作り方（法務推奨）：**my_words に♡の印の列を足すだけ**（例 `liked` boolean／`liked_at`・文は既存の `sentence`）。新テーブルは作らない。利用者をまたいだ集計（ランキング等）と共有キャッシュへの投入はしない。
- 付けられる場所（アプリだけで可）：単語リスト／単語帳／復習カードの例文の横に「♡」（説明は「この例文を保存」）。拡張のポップアップから付けるなら語に印だけ（拡張 v1.2.12 以降）。
- 上限と不変：1話あたり 10 件。その1行だけ（範囲選択なし）。保存した文は書き換え不可。出所はアプリ内の例文（OpenSubtitles 由来）だけ＝Netflix 画面字幕の行は保存しない。
- 出さないもの：訳だけを並べる画面・画像として保存・SNS 投稿。CSV/Anki に文と訳は出さない（♡の有無の列は可）。
- プライバシーポリシー「学習データ」の「保存した単語、例文（字幕の一文）」の後ろに「、例文に付けたお気に入りの印」を足す（反映と同時か前・⑤）。
- 文言：見出しは「♡を付けた語（例文つき）」。「セリフ集」「名セリフ」「お気に入りのセリフ」は使わない。

## 4. 単語帳の画面の役割と並び
- 役割：「自分で選んだ語」の棚。上から ①♡を付けた語（例文つき・語が見出し・例文は従）②特に覚えたい語（★・今の一覧・stats タイルはそのまま）。空の節は見出しを出さず一行の案内だけ（「気に入った例文は ♡ で残せます」）。
- 開く理由が生まれる導線（押しつけない）：
  - ホーム：「今日の語」カード＝♡の付いた語を1つ（語が見出し・例文を添える・無ければ出さない）→タップで単語帳。
  - 復習の終わり（おつかれさま画面）：「★を付けた語を単語帳で見る」のリンク一行（付けた時だけ）。
  - 単語リスト：★／♡を付けた直後のトースト「単語帳に入れました」→タップで単語帳。
- 下タブの件数バッジ：★の語の数（今と同じ関数）。赤ではなく今の灰色のまま。

## 5. 拡張の変更が要るか
- **要らない範囲**（v1.2.11 提出・v1.2.12 審査待ちのまま可）：1 の既定変更（DB）、2 の★の追加（アプリ側）、3 の♡（アプリ内の例文に付ける）、4 の画面。
- **要る範囲**（v1.2.12 以降）：(a) ポップアップに「★ 特に覚えたい」(b) ポップアップに「♡」（語に印だけ・画面字幕の行は保存しない）(c) background.js:67 の「他作品で出会った語」の印を `in_wordbook=is.true` で絞るのをやめ、保存語ぜんぶ（または ★＋覚えた語）にする＝1 の既定変更で別端末の未★語が印から落ちるのを防ぐ。(c) は1行の変更。
