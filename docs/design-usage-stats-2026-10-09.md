# ベータの利用データ（週次）の設計（2026-10-09・オーナーと合意）

> 目的: プラス（月¥480）の払う割合と上限の数（月の新規生成 無料5話／プラス30話・初めて復習する語 無料1日20語）を
> 「ベータの利用データで最終判断」する（docs/design-paid-features-2026-10-08.md）。その判断材料を週ごとに見る。

## 1. 数えるもの（オーナー確定）
| # | 項目 | 名前（lib/usageEvents.js） |
|---|---|---|
| 1 | アプリを開いた人（全体・ログイン中） | `open`（＋行の L） |
| 2 | 作品・話の復習を始めた | `work_review` |
| 3 | 作品まとめ復習を始めた | `work_all_review` |
| 4 | 作品・話のクイズを始めた | `work_quiz` |
| 5 | あゆみを下のタブから開いた | `journey_tab` |
| 6 | ホームの学習した日からあゆみを開いた | `journey_grass` |
| 7 | 週ごとの推移が画面に表示された（半分以上・開くたび1回） | `trend_seen` |
| 8 | 毎日の復習の語数＝**基準を設けずそのまま記録**（初めて／継続／期日が来て残った）。端末ごと（firstReview が端末にしか無い＝無料の上限と同じ数え方） | 行の `r:{n,c,l}` |
| 9 | 月の新規生成の分布（1人が月に何話・5話超／30話超の割合） | 既存の `gen:month:<YYYYMM>:<番号>` を読む |
| 10 | 予習の流れ: ①単語リストを開いた → ③カードを始めた → ④重要語を見終えた → ⑤残りも見た → ⑥完了。**どの段階でも途中離脱**を「何割まで（1割きざみ）×抜け方」で | `list_open`・`walk_*`・`exit_<list|core|rest>_<0-10>_<walk|x|later|nav|close>` |

人数と回数の両方を出す。作品名・話の番号・単語・時刻は送らない。

## 2. どこで数えるか（オーナー確定＝案1）
- アプリ（lib/usage.js）が端末で「その日の合計」をため、タブが隠れた時・1時間おき・開いて15秒後に `POST /api/usage` へ**上書き**で送る（二重計上なし・送り損ねは次で追いつく）。
- サーバーは Upstash の HASH `usage:d:<YYYYMMDD>`、フィールド `<人の番号>.<端末の番号>`＝**1人＋端末×1日1行**、120日で消える。
  - 人の番号＝`hashId('u:'+uid)`（ログイン中）／`hashId('d:'+端末キー)`（未ログイン）。端末の番号＝`hashId('d:'+端末キー)`。生の ID・IP は保存しない（レート制限も端末の番号で・1時間30回／1日200回）。
  - ログインしたら同じ端末の未ログインの行（その日）を消す（端末の合計がログイン後の行に含まれるため）。
- 1回の送信で Upstash の操作は 5〜6 回（レート制限＋書き込み）。100人でも無料枠に十分収まる。
- 使わないもの: Vercel の自前イベント（有料プランのみ）・Supabase（個人データと置き場を分ける・GRANT の罠）・拡張。

## 3. 見せ方（オーナー確定＝案1）
`node --env-file=seed/.env seed/weekly-stats.mjs [週数] [--csv[=パス]]`
- ① 今の表（OS 契約）② 利用者とプラスの機能 ③ 予習の流れ＋抜けた場所 ④ 毎日の復習の語数 ⑤ 月の新規生成＋判断の目安。
- 計算は next-app/lib/usageReport.js（テスト: next-app/scripts/usage.test.mjs）。
- 月の生成数は40日で消えるので、読むたびに分布（人数のみ）を `stat:genmonth:<YYYYMM>` に400日保存。
- `--csv`: 1人＋端末×1日の生データ。**既定は ~/cinelearn-usage-<日付>.csv（リポジトリ内には書けない）。共有しない・コミットしない・暗号化ディスク（FileVault）上だけ・120日以内に消す。**

## 4. プライバシー（法務部の確認つき・オーナー確定＝案1）
- 仮名の行（運営はペッパーとアカウント表を持つ＝照合できる）なので**個人情報として扱う**。PP を更新（2026-10-09）: 取得する情報「利用状況の統計」・利用目的「品質改善と機能・料金設計の検討」・Upstash の保存期間（レート制限24時間／月の生成数40日／統計120日）・§5 を同期。
- 月の生成数のキーを生の uid から番号へ（`genMonthKey` が hashId を使う）。切り替えた 2026-10 だけ数え直し（ベータは数えるだけなので実害なし）。分布は16hex のキーだけ数える＝古い生 uid のキーで二重にならない。
- 設定「📊 利用統計を送る」（既定オン・この端末だけ・オフでためるのも送るのも止める）。法律上は必須ではないが保守的に置く（法務）。
- 削除依頼（法35条）: `node --env-file=seed/.env seed/delete-usage.mjs <利用者ID>` → `DELETE /api/stats`（その人の行と今月・先月の生成数）。未ログインの端末の行は ID とつながらないので消せない（120日で消える）。
- ペッパー（CL_HASH_PEPPER → 無ければ CL_SEED_SECRET）は env だけ・ログに出さない・**変えると番号が全部変わる**。
- 前からある PP の不足（法務指摘・今回は直さない）: 事業者名・連絡先・安全管理措置（法32条）、保存先の国（Upstash/Supabase）。正式版の前に。

## 本番での確認
1. デプロイ後、アプリを開いて少し操作（作品・話の復習やあゆみなど）。
2. タブを閉じる（または1時間待つ）。
3. `node --env-file=seed/.env seed/weekly-stats.mjs 1` を実行し、② の「開いた人」に自分（1）が出る・操作した項目の回数が出ることを確かめる。
4. 削除の確認（任意）: `seed/delete-usage.mjs <自分の利用者ID>` → もう一度表を出して自分の行が消えていること（タブを開いたままだと次の送信で戻る）。

## 注意
- 数え始めはデプロイ日。開発時（npm run dev）は React の二重実行があるが、付け直しを検出して二重に数えない作り。
- 単語リストの「何割まで見たか」は、予習カードへ進んだ時点でその回を閉じる（カードから一覧に戻ったあとは測らない）。
- スマホでタブを閉じた時の送信は届かないことがある（keepalive）。次に開いた時、前の日の分も含めて送り直す。
