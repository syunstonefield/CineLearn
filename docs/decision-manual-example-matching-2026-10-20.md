# 決定: 手動追加で例文・📍時刻が付かない問題の解決策（2026-10-20・/decide 討論）

参加: engineer / legal / security（R1 独立 → R2 相互反論 → 司会が実コードで裏取りして収束）。
Claude は弁護士ではない。法務の判定は保守側から見た設計上の判断で、法的な最終判断ではない。
**オーナー確認待ち。** コードは未変更。

## 発端
単語リストの「この話の単語を追加」で、スペルが正しいのに例文や📍時刻が付かないことがある（オーナー報告・話は不明）。
原因を `lib/subtitles.js` を node で実行して確定した（推測ではない）:

| 原因 | 再現 |
|---|---|
| 変化形の取りこぼし | watch→watches, strong→stronger, knife→knives, flee→fled, realize→realised, multiverse→multi-verse はすべて一致しない |
| ♪のある行を丸ごと捨てる | セリフ行に♪が1つあるだけで検索対象外 |
| SRT の形式崩れ | 空行にスペース／空行なし→全体が1キュー（例文が長文・📍が冒頭）。CR のみ→0キュー |
| 探しに行かない語 | 頻出4000語（court, evidence, strong, hold…）・2語以上・2文字以下は仕様で拒否 |
| 字幕ファイルの取り違え | raw cache（30日）失効後は検索し直し＝生成時と別 file_id になり得る。話数一致ゼロなら別話の字幕にフォールバック |

## 決めたこと（3部署一致・実コードで裏取り済み）

### A. 変化形の補強 — 条件付き可
- **規則の機械追加は不可。** 比較級(-er/-est)・ves・英米綴り・複合語の分かち書きは「対応表に載せた語だけ」に限り、**逆剥がし（-er を外す等）はしない**。理由: 品詞を知らない照合器では numb→number、safe→saves、filled→filed、floor→flour、setup→set up に当たり、誤一致した字幕文が plus→drama 昇格で**出所付きの引用になる**（法務: 語を含まない文は引用の必然性が無い＝32条の根拠が1件ずつ崩れる。例文数の増加より優先度が高い）。
- -es（s/sh/ch/x/z/o 語尾）と不規則動詞の表拡充は規則で可。
- 導入前に **vocab_cache 全行で exampleContainsWord の新旧差分検査を必須**（新たに true になる語＝昇格候補を目視）。
- 二次の防御として、生成時に drama 例文の数に上限を固定（qualityGate 直前・キュー数の1割または固定値。超過分は「語は残し例文と📍だけ空」。plus に落とすのは不可＝AI 作例の出所表示が嘘になる）。現 `MAX_WORDS=300` は語数の上限で例文数の歯止めではない。

### B. ♪の扱い — 条件付き可
- ♪〜♪で囲まれた区間は**本文ごと**除く（記号だけ消すと歌詞本文が残り、歌詞は別の著作物で出所表示も不正確）。♪で始まり閉じが無い行は歌詞扱い。判定は結合後ではなく**行ごと**。
- "subtitles by"・"original air date"・"opensubtitles" の除外は維持し、**URL を含む行も除外**（OS は誰でも上げられる＝宣伝文の混入防止）。

### C. SRT の頑丈な読み方 — 可（対象は3つ）
- 直すのは `parseServeCues`・`parseSrt`・**`parseCues`（生成時の📍・subtitles.js:452）の3つ**。1つの分割関数に統一しないと「字幕tsSec二重パスの罠」が再発する。実行で確認: 形式崩れの SRT は生成側の tsSec も null になる。
- 改行正規化（\r\n/\r）・BOM 除去・空白のみの空行・タイムスタンプ行で区切る。
- 上限を追加: 1キュー長・キュー数・SRT 全体サイズ（今は最小長しか無い）。
- 注意: `parseSrt` は短すぎ判定（opensubtitles.js:279）にも使われるので、採用される file_id が変わり得る。

### D. 字幕 file_id の記録と再利用 — 条件付き可（新列方式）
- `vocab_cache` に新列 `subtitle_file_id`（数値）・`episode_match`（'exact'|'fallback'|null）。**別テーブルは不要**: 本番は列指定 GRANT（repo SQL）かつ 2026-10-15 に anon 直読み REVOKE 済み（pending-fixes）＝新列は既定で anon から読めない。条件: anon でその列を SELECT すると拒否される回帰テストを置く。
- **`VOCAB_ROW_SELECT` には混ぜない**（マイグレーション前に 400 で層1と /api/vocab が止まる）。手動経路専用の select で service_role が読む。書込は `isMissingColumn` の再送パターンに揃える。
- file_id は**サーバの vocab_cache からだけ読む**。リクエスト本文から受けない。
- 失効後の取り直しは**手動追加を起点にした時だけ**（自動で温め直さない）。TTL は30日のまま延ばさない。
- DL 失敗の扱い: OS が 404/410 で「無い」と確定した時だけ file_id を消す（権利者申立てで消えたファイルを再使用しない）。5xx・timeout・os_quota では消さない。検索へ戻るのは1回の取り直しにつき1回、同じ DL 枠から差し引く。`osDownload` は今 'os_download' 一括で投げるので、ステータスを区別して投げ直す。
- バックフィルは `raw.fetched_at ≤ vocab.updated_at` の行だけ（失効後の手動再取得で provider が別 file_id に上書きされた行がある）。生成が raw cache に当たった場合 episode_match は null 可。
- 直接 DL は検索＋最大3DL より OS 枠を減らす（security）。

### E. カードの案内文 — 可（条件あり）
- 3分類: **今後も付かない**（common_word / multi_token / too_short）／**あとで付くことがある**（no_raw / os_quota / rate_limited / unavailable / network / login_required / **subtitle_fetch_failed**）／**探したが無かった**（no_match / no_subtitle_file）。
- 文言: 「字幕が用意できると付きます」は不可（当社が字幕ファイルを用意・保有・配布しているように読める）。「例文はあとで付くことがあります」「この回では例文が見つかりませんでした」等。OpenSubtitles 名・枠切れは**引用の出所以外には出さない**。
- 外向きの理由コード: `os_quota` は `unavailable` にまとめる（枠を使い切れたことを教えない）。
- 現行カード文言「例文はまだありません（字幕が用意できると付きます）」は**直す対象**。

### F. 頻出語・フレーズのゲート緩和 — 現案は不可。安全な代替のみ可
- 「非頻出語を1つ含むフレーズなら raw を照合」は不可: 低頻度語＋隣の語で**同じ語の2回目以降の出現を選べる**＝「1語なら常に同じ最初の1文」という今の防御の要が外れる。回数上限だけでは3アカウントで2週間で1話全文に届く。
- 資料の例 strike a deal は strike も deal も頻出語で例として成立しない。
- 代替（採用）: フレーズは**その話の vocab_cache 内だけ**で探し、raw は照合しない。raw 照合を許すなら「句動詞・コロケーション辞書に載った句のみ＋句専用の枠（例 5/日）」が最低条件。

### G. 話数不一致フォールバック — 現状維持は不可（段階案）
- 別話の字幕に `📺作品 SxE` を出すのは48条の出所表示が事実と違う（122条の罰則対象になり得る）。**どの段階でも、話数を誤ったままの表示は出さない**（法務の譲らない点）。
- 第1段: 生成で `episode_match` を記録し、**fallback 行の出所表示は作品単位（話数なし）**にする。手動追加では fallback 行を使わない。
- 第2段: 公開前の期限までに、生成でも「話数一致ゼロなら字幕なし」に切り替え、既存の fallback 行だけ作り直す。
- G の判定では feature_details が null の候補と、はっきり別話数の候補を分けて数える。

## 討論で見つかった既存の穴（今回の案とは別に直す・pending-fixes に登録）
1. **頻出語ゲートの迂回**（Med・再現済み）: `manualWordProblem` は綴りそのものしか見ない。knowed / thinked / sayed が通り、`getWordVariants` が know / think / say を照合候補に加える（"I know it." に一致）。修正: 語尾を外して原形に戻した形で判定（活用形全体では判定しない＝bedding/briefing/outing/dressing/grounded を巻き込まない・実行で確認）。evening→even 等は例外表。**A を直さずにこのゲートだけ足すのは不可**（偽の変化形が原因の半分）。
2. **手動取り直しに DL ゲートが無い**（Med）: `exampleDlEligible` は通常経路（route.js:317）にあり手動経路（:246）に無い。1人5話×最大3DL=15回/日、共有上限700は約47アカウントで枯れる。
3. **ReDoS**（Med・再現済み）: 語長・句の語数に上限が無く、句の正規表現は「間に0〜2語」を許す。同じ語40回のキューに「同じ語12回＋一致しない語1つ」の句で **1.17秒/キュー**（8語 26ms・10語 160ms）。修正: 語長64・句5語・1語あたり候補32まで。`exampleContainsWord` が毎キュー正規表現を作り直している（1回だけ作る）。手動経路は multi_token で句を拒否しているので露出は anchor 経路（拡張）側。
4. **累計上限が無い**: 話60/日は日次のみ。30日で1800文＞1話の字幕（600〜900キュー）。方針: 返した**異なるキューの種類数**で数える（同じ文を何度返しても漏れは増えない）。1話につき30日で80種類（単語リストと同じ約1割）を案とし、**まず2週間「種類数の記録だけ」して正規利用を阻害しないか測ってから数値を決める**（本文は記録しない）。

## 保留＝要オーナー判断
- G 第2段（生成でも別話を拒否）: 「字幕なし」が増える UX コスト vs 出所表示の正確さ。法務は第2段を公開前の期限にすることを条件に段階案を受け入れた。
- 累計上限の数値（80種類/30日 は仮）: 2週間の計測後に決める。
- F の代替で十分か（フレーズは vocab_cache 内のみ）。
- 字幕例文の量を「1話あたりキュー数の1割」まで絞るか（現状は中央11%・最大27%。絞ると既存の話から例文が消える）。
