# 画面の字幕行を例文として保存するか（2026-10-31 /decide・オーナー判断待ち）

## 問い

拡張のクリック保存で、例文に「画面に表示されている配信字幕の行」をそのまま保存する方式に切り替えるべきか。
オーナーの依頼は「過去の決定（2026-06-14 経路②→①畳み込み）を一旦置いて再度の見解を」。

## きっかけ（実データ）

- Suits S1E1 の 31:50〜32:01 で保存した4語（symmetry / mergers / acquisitions / anchored）に例文が付かない。
  本番 API で再現し、OpenSubtitles（OS）の字幕ファイルにその場面の台詞が無いことを確認した（字幕ファイル自体は最後まである）。
- オーナー報告: Suits S1E2・Falcon and the Winter Soldier でも同様（このセッションでは未検証）。
- 同日の対策（OS の別候補ファイルを試す 4d59120・照合窓 ±45→±180 秒 f9e77fd）では改善しなかった。

## 前提の整理

- 拡張は既に「DOM 読み」方式。論点は読み方ではなく、読んだ行を**保存するか**。
- 現行でも画面の字幕行は保存せずに3か所で使っている: ポップアップ表示／/api/example の照合アンカー／/api/claude wordsense（Claude Haiku の文脈訳）。
- プライバシーポリシーは「字幕の一文は照合と訳の生成にのみ用い、当社サーバーは保存しません」と明記（privacy/page.js 76-77・141 行で確認）。
- 例文の和訳を作る経路（/api/claude mode:'sentences'）は、訳と一緒に元の文を共有キャッシュ（translation_ctx_cache.sentence_sample）に書く（route.js 438 行で確認）。画面の行をそのまま流すとサーバーに溜まり他ユーザーと共有される。

## 討論（R1 独立 → R2 敵対）

| 視点 | R1 | R2 後 |
|---|---|---|
| 法務・保守 | A（現状維持）＋場面しおり。B/C/D は赤 | しおりだけでは不足と認め、AI 作例を追加。**法人化・弁護士確認・公開切替の前に配信字幕本文をサーバーに保存しない**は不譲 |
| 法務・攻め | C（黄・条件付き） | C を公開切替に入れるのは撤回。A＋しおり＋端末内保存で公開、C は有料化前に弁護士確認を経て再審議 |
| エンジニア | C（出所フラグ必須） | C 維持。しおりは配信の作品 ID が保存データに無く、Disney+・Prime Video・スマホでは戻れない＝弱い。端末内保存（D）は不採用 |
| 利用者代弁 | B | C に下げる（ストアから消えるリスクの方が重い）。「例文が空のまま放置しない」「スマホでも見える」は不譲 |

選択肢の定義: A＝OS の1文のみ／B＝常に画面の行／C＝OS で当たらない時だけ画面の行（本人の単語帳・非共有・出所表示）／D＝画面の行を端末内だけに保存。

## 確定した点（4者一致）

1. **B は採らない**（OS で当たる語まで配信字幕に置き換えると、リスクだけ増えて得が無い）。
2. **D は採らない**（スマホ・別端末の復習で例文が空になる）。
3. **場面しおりは主役にならない**（配信の作品 ID が無い・他サービスとスマホで戻れない）。
4. C を入れるなら最低条件は次のとおり（法務2者・エンジニアが一致）:
   - 出所フラグ（例: example_src='screen'）を付け、同期できない時は例文ごと送らない（fail-closed）
   - 共有キャッシュ・vocab_cache・CSV/Anki 書き出しに入れない
   - 画面行の和訳は、保存しない経路で作る（クリック時の wordsense と同時に作り my_words に直接入れる案＝エンジニア）
   - “…” で囲み「作品名 SxE（画面字幕）」と出所を表示・削除窓口の対象
   - プライバシーポリシー改定 → CWS データ開示の再申告 → 拡張 v1.2.11 の再審査、の順
   - 今例文が無い語は救えない（再クリックが必要）

## 割れた点（価値・リスク選好の分岐＝オーナー判断）

画面の行を**いつ**サーバーに保存してよいか。

- 保守側: 法人化・弁護士の単発確認・公開切替の後。どうしても先に入れるなら、オーナーが書面でリスクを受容し、fail-closed とポリシー改定を先に済ませること。
- エンジニア・利用者代弁: 条件を満たせば今入れてよい。

## オーナーへの選択肢

1. **段階導入（推奨）**: 公開切替は現行（A）のまま行い、OS で例文が無い語には AI 作例（語と語義だけから作り、字幕行は入力しない・「AI 作例」と明示）を付ける。C は法人化と弁護士の単発確認の後、有料化前に入れる。
2. **今すぐ C**: 上の最低条件をすべて満たしてから入れる。公開切替は v1.2.11 の再審査ぶん遅れる。オーナーの書面でのリスク受容が前提。
3. **A のまま**: AI 作例も付けない。

## 副次的に見つかった点

- 照合窓を ±180 秒に広げたことで、窓の中の**別の台詞**が例文になる可能性が上がった（エンジニア指摘）。アンカー照合（via='anchor'・'anchor_alt'）以外の当たりは「他人の文」になり得る。採る選択肢に関わらず、窓の当たりの扱いは見直し対象。
- 文脈訳（wordsense の `ja`）は既に画面の行から作られ、my_words に保存されている（訳であって本文ではない）。法務の再確認事項。
- 法務2者とも「OS で当たった時は画面の行ではなく OS の文を Claude に送る」を提案。エンジニアは、文脈訳がポップアップ表示時に呼ばれ OS 照会より先に走るため非現実的と反論。未決。
